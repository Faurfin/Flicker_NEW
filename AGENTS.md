## 🎯 Роль

Вы помогаете развивать репозиторий «Фликера»:

- `frontend/` — Flutter-клиент (package `frontend`): тёмная тема, вход по телефону, профиль, поиск, QR-приглашения;
- `backend/` — API на FastAPI (Python 3.11): SQLAlchemy async + PostgreSQL + Redis; рядом лежит экспериментальный Go-сервис `backend/go_app/`.

Каталог `flutter/` — чек-аут Flutter SDK, это **инструмент, а не код проекта**: не править, не коммитить изменения в нём.

Пишите **чистый, короткий, масштабируемый** код. Не раздувайте scope. Не «улучшайте всё подряд» без запроса.

## ✅ Чеклист перед новой функцией

Перед тем как написать новый код, **явно** проверьте четыре пункта.

**1. Дублирование**  
Есть ли уже такой или почти такой код в `frontend/lib` или `backend/app`? Поищите по имени, смыслу, endpoint, экрану. **Если есть — переиспользуйте, вынесите общее, не копируйте.**

> Известный долг: URL API (`https://api.web-flicker.online`) продублирован в `api_client.dart`, `login_screen.dart`, `verify_code_screen.dart`, `profile_setup_screen.dart`, `search_screen.dart`, `qr_screen.dart`, `registration_screens.dart` и `otp_screen.dart`. Новый запрос должен идти через `ApiClient` с baseUrl, а не восьмой копией. Палитра цветов (`#0A0A0A`, `#C7F431`, `#161616`, `#27272A`, `#A1A1AA`) скопирована в каждый экран — новые цвета должны появляться в общей теме, а не в `_bgColor` десятого файла. Экраны `otp_screen.dart`/`registration_screens.dart` — легаси-копии `features/auth/`: новые флоу только в `features/`.

**2. Актуальность API**  
Используете ли вы современный API языка и пакетов проекта?

- Dart 3 / Flutter: null-safety, `super.key`, records, `switch`-выражения; `WidgetsFlutterBinding.ensureInitialized()` перед async в `main`; `PopScope` вместо устаревшего `WillPopScope`.
- Python 3.11 / FastAPI: `lifespan` вместо `@app.on_event`; SQLAlchemy 2.0-стиль (`select(User)`), только async-сессии через `get_db`; pydantic v2 (`model_validate`), `pydantic-settings` для конфига; аннотации типов.
- Redis: TTL на коды (`setex`), ключ `sms:{phone}` — не изобретайте свой формат.

Не тащите устаревшие паттерны «из памяти 2019 года»: синхронные сессии `sqlalchemy.orm.Session` в async-эндпоинтах, `@app.on_event`, `WillPopScope`.

**3. Можно ли короче?**  
Спросите себя: «Можно ли выразить то же яснее и короче?» Уберите лишние переменные, вложенность, обёртки «на будущее».

**4. Масштабируемость**  
Легко ли это расширить без копипаста?

- конфиг и константы вместо размазанного хардкода (URL, цвета, таймауты);
- одна ответственность на функцию;
- границы модулей из [ARCHITECTURE.md](./ARCHITECTURE.md): UI ≠ сеть ≠ бизнес-логика ≠ БД.

Если хотя бы на один пункт ответ «нет» или «не уверен» — **остановитесь, поправьте подход**, потом пишите.

## ✨ Чистый код

### Делайте

- Имена, которые читаются без комментария: `sendCode`, `verify_code_and_login`, а не `doStuff` или `data2`.
- Функция или метод делает **одно** дело.
- Маленькие понятные блоки, ранняя проверка ошибок (guard clauses).
- DRY: общая логика живёт в одном месте — `ApiClient`, `app/services`, `app/schemas`.
- KISS и YAGNI: решайте текущую задачу, не стройте framework «на вырост».
- Ошибки в Python заворачивайте с контекстом и поднимайте типизированные исключения (`raise HTTPException(status_code=404, detail=...)` — на HTTP-слое, а не в сервисе).
- При росте API новый сценарий оформляйте как `service` + `router` в `app/api/`, а не раздувайте `main.py`.
- При росте клиента новые экраны — в `features/{feature}/ui/` по образцу `features/auth/`, а не плоским файлом в `lib/`.

### Не делайте

- **Лишние комментарии.** Комментируйте только *почему* (неочевидный trade-off, баг платформы), а не *что* — это видно из кода.
- Комментарии-нарратив (`// отправляем post запрос`), закомментированный мёртвый код, TODO без контекста.
- Дублирование UI, HTTP или логики «чуть-чуть по-другому» в двух файлах (см. долг про легаси-экраны выше).
- Магические числа и строки без имени (пороги, URL, timeout, ключи `SharedPreferences`) — выносите в константы рядом с использованием или в общий модуль.
- Новые зависимости без явной необходимости и без согласования с текущим стеком.
- Секреты, пароли и прод-адреса в новых местах: учётные данные БД уже захардкожены в `config.py` и compose — не размножайте долг.
- Моковые данные, замаскированные под реальные: если блок пока заглушка (`AlienProfileScreen`, `followers_count = 24`, «Экран N»), это фиксируется в разделе «Известные ограничения» [README.md](./README.md), а не выдаётся за готовую функциональность.

## 🧱 Структура и границы слоёв

| Слой | Разрешено | Запрещено |
|------|-----------|-----------|
| `core/api/api_client.dart` | Базовый URL, таймауты, заголовки, единый `Dio` | Знание об экранах и доменах |
| `features/*/ui` | UI, локальный state, навигация | Прямой HTTP в обход `ApiClient`, бизнес-логика |
| `features/*/data` | Репозитории поверх `ApiClient`, DTO клиента | Виджеты, строки интерфейса |
| `app/api/` | HTTP: разбор payload, коды ответов, `HTTPException` | SQL-запросы и бизнес-правила (сейчас нарушается в `users.py` — не углубляйте) |
| `app/services/` | Бизнес-логика: OTP, вход, профиль, рекомендации | Формирование HTTP-ответов |
| `app/schemas/` | Pydantic-DTO и валидация | Логика и доступ к БД |
| `app/db/` | Engine, сессии, модели, `get_db` | HTTP и бизнес-логика |
| `app/main.py` | Wiring: CORS, статика, роутеры | Копипаста SQL и логики из сервисов |
| `go_app/` | Эксперименты с Gin | Дублировать прод-логику FastAPI |

Соблюдайте существующие имена: **`frontend/`** (package `frontend`) и **`backend/`** (FastAPI) + `backend/go_app/` (эксперимент). Каталог `flutter/` не трогаем.

## 🛠️ Специфика стека

### Flutter / Dart

- `const`-конструкторы там, где это возможно.
- Отменяйте подписки и освобождайте контроллеры: `TextEditingController`, `FocusNode`, `PageController`, `AnimationController`, `Timer`.
- Не блокируйте UI-поток тяжёлой работой; сеть — только через `ApiClient` с timeout.
- **Весь HTTP — через `ApiClient`** (`package:dio`). Экран не должен импортировать `package:http` и собирать `Uri` вручную — это текущий долг, новые экраны его не повторяют.
- Ключи `SharedPreferences` — именованные константы (`isFirstLaunch`, `current_phone`), не строковые литералы в разных местах.
- Цвета — из общей темы (когда появится) или хотя бы из констант дизайн-системы; не хардкодьте `Color(0xFFC7F431)` в каждом экране.
- SVG — через `flutter_svg` с `ColorFilter.mode(...)` для перекраски.
- Новые идентификаторы — на английском; пользовательские строки интерфейса — на русском, как в текущем UI.

### FastAPI / Python

- Все эндпоинты — `async def`; БД только через `Depends(get_db)` (async-сессия); никаких синхронных `Session`.
- SQL — в стиле SQLAlchemy 2.0: `select(User).where(...)`, результат через `(await db.execute(stmt)).scalars().all()`.
- Pydantic-схемы на все входы и выходы; общие DTO — в `app/schemas/`, не инлайн в роутере (сейчас `UserProfile` инлайн в `users.py` — не копируйте приём).
- Коды OTP — в Redis с TTL, никогда не логировать в прод (сейчас печать в лог — заглушка SMS-шлюза).
- Не логируйте секреты и полные персональные данные; `echo=True` на движке — временно для отладки, в прод убрать.
- Конфиг — только через `app/core/config.py` (`Settings`), с осмысленными fallback.
- Схема БД — через `Base.metadata.create_all` (миграций нет): новые таблицы добавлять в `models.py`; изменение существующих колонок требует отдельной задачи (введение Alembic).
- **Безопасность**: текущая «авторизация» — номер телефона в query и фейковый токен. Новые эндпоинты не должны повторять этот паттерн; при добавлении защищённых данных сначала ввести настоящую JWT-проверку (задача согласуется отдельно).

## 📜 Контракты и документация

- Меняете request или response API → синхронно обновляете клиент (`features/`, `ApiClient`) **и** [README.md](./README.md) / [ARCHITECTURE.md](./ARCHITECTURE.md).
- Добавили, удалили или переименовали публичный модуль, функцию или пакет → обновляете `ARCHITECTURE.md`.
- Появилась заглушка в UI или обходное решение → строка в «Известные ограничения» в `README.md`.
- Не коммитьте: `frontend/build/`, `frontend/.dart_tool/`, `.venv/`, `__pycache__/`, `backend/static/avatars/` (пользовательские аватарки), секреты и локальные ключи.

## 🔁 Порядок работы агента

1. Прочитайте задачу.
2. Откройте релевантные файлы и `ARCHITECTURE.md`.
3. Пройдите чеклист из четырёх пунктов выше.
4. Внесите минимальный diff.
5. Проверьте: нет дублей, имена ясные, нет мусорных комментариев.
6. При необходимости обновите документацию.
7. По возможности прогоните проверки: `python -m compileall backend/app`, запуск API и `curl` эндпоинтов, `cd frontend && flutter analyze` (полный `flutter test` пока не проходит — см. ограничения).

## 📣 Манифест

> Перед каждой новой функцией: **не дублируй → используй актуальный API → пиши короче → оставляй место для роста.**  
> Код должен читаться без комментариев. Документы — источник правды о структуре, код — источник правды о поведении.
